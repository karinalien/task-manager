# Рабочие примеры для Task Manager

## Текущий пример: трекер привычек

Выбран пользователем 20 октября 2026 года. Отдельный публичный репозиторий: [karinalien/habit-tracker](https://github.com/karinalien/habit-tracker). Исходники Task Manager в него не переносятся.

Подготовлен стартовый проект Node.js 24 без зависимостей: библиотека привычек, ежедневные отметки, консольная демонстрация и 3 теста. Пока данные примера живут в памяти. Это основа для задач, а не законченный сайт трекера.

Примеры задач: удаление привычки с обработкой неизвестного ID; подсчёт серии; сохранение в JSON; веб-интерфейс; документация API. Через Task Manager генерируется ТЗ и ветка, но сам код задачи автоматически не реализуется.

## Декомпозиция большой задачи

На доске активного проекта выберите «Разбить на подзадачи», введите описание и нажмите «Разбить с ИИ». Раскройте строки и проверьте требования, предварительные часы и компетенции перед дальнейшим планированием.

**Экспорт задач**

> Добавить экспорт задач текущего проекта в CSV. Выгружать только название, статус и исполнителя. Включать карточки из Done. При пустом проекте возвращать CSV только с заголовками. При ошибке показать сообщение и не скачивать файл. Добавить тесты обычной и пустой выгрузки. Импорт CSV не добавлять.

Сверьте, что в выгрузку попадают только задачи текущего проекта. Проверьте поля файла, включение Done, поведение пустой выгрузки и обработку ошибки. Проверьте, что в черновике есть тесты и не появился импорт.

**Серия отметок в трекере привычек**

> В трекере привычек считать текущую серию дней для выбранной привычки. Две отметки за один день считать одной. Не учитывать отметки других привычек. При пропуске календарного дня серия прерывается, при пустой истории результат 0. Добавить тесты пустой истории, повторной отметки и пропуска дня. Хранение данных не менять.

Сверьте, что расчёт относится к одной привычке и учитывает уникальные календарные дни. Проверьте число для пустой истории, поведение при пропуске и тесты.

Черновик доступен в той же вкладке после перезагрузки. При сбое повторной генерации доступны предыдущие строки. «Заменить список с ИИ» заменяет их после успешного ответа. Предпросмотр не добавляет карточки на доску и не создаёт ветки.

## Будущий пример: сайт театра

Оставлен по пожеланию пользователя на следующий этап. Сейчас репозиторий и сайт не создаются. Возможные задачи позднее: афиша, страницы спектаклей, фильтр по датам, форма обращения. Для проверки переключения проектов сейчас достаточно заглушек двух репозиториев в автоматических тестах.
