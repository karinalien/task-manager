# R3: декомпозиция задачи и правка черновика

25 ноября 2026. Ветка `r3-task-decomposition` от `origin/main` (`33ba92b`). Пункты 3–6
плана Карины на первую неделю.

- На доске действие «Разбить на подзадачи» открывает форму большого описания.
- `POST /api/ai/decompose` принимает `projectId` и `prompt`. Для действующего
  проекта общий клиент LLM возвращает 2–5 подзадач. Для каждой проверяются название,
  описание, предварительные часы и ID групп из существующего справочника.
- Черновик редактируется по строкам. Пользователь может добавить или удалить
  подзадачу (до восьми строк всего), изменить текст, оценку и компетенции.
  Исходный запрос и правки восстанавливаются после перезагрузки той же вкладки,
  отдельно для каждого проекта.
- Сервер и редактор проверяют весь ответ до замены списка. Пустые поля,
  повторяющиеся названия или описания (без учёта регистра и пунктуации),
  неверные часы, компетенции и посторонние поля отклоняются. При ошибке сети,
  тайм-ауте или неверном ответе остаётся предыдущий черновик и доступен повтор.
- Генерация и ручная правка работают до этапа записи карточек. Сохранение
  плана и распределение по спринтам относятся к следующему этапу. Вызов
  не создаёт задач в JSON и не обращается к GitHub.

## Ограничение по проекту — 26 ноября 2026

Если запрос явно указывает текущий или выбранный проект, сервер
сохраняет исходную формулировку условия в описании подходящей подзадачи,
даже если её пропустила модель. Уже присутствующая фраза повторно не
добавляется. Подзадача выбирается по совпадению значимых слов исходного
условия с названием и описанием.

Автоматические проверки воспроизвели пропуск в ответе модели и подтвердили,
что API добавляет исходное условие. Проверены выбор подходящей строки,
отсутствие повторной вставки и предельная длина описания.
`npm test` — 198/198, `npm run check` — 53 файла, `git diff --check` — успешно.

Повтор CSV-примера на Qwen3.5-9B через локальный API вернул три подзадачи
за 70,1 с. В описание реализации вошла исходная фраза «Добавить экспорт
