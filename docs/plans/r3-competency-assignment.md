## Объём и правила

- Подтверждённая задача получает оценку estimatedHours (null или 0.5–10000, шаг 0.5), requiredGroups (стабильные ID) и requiredTechnologies (справочник).
- Часы — план полного объёма, не табель и не остаток фактически затраченного времени. Спринтов/календаря пока нет: capacity — общий бюджет текущего рабочего периода во всех проектах.
- В загрузку входят назначенные подтверждённые задачи всех проектов, включая архивированные; Done/черновики исключаются. Оценки отсутствующих значений не выдумываются, число неизвестных показывается отдельно.
- Подбор требует оценки и хотя бы одной группы. Все требуемые группы обязательны, технологии повышают приоритет, затем учитываются свободные часы; грейд пока информационный.
- Собственная текущая задача исключается из нагрузки при подборе. При неизвестных оценках/нехватке часов кандидат не рекомендуется. ИИ-исполнитель не рекомендуется, поскольку выполнение ещё не подключено.
- Подбор только читает данные. Человек выбирает рекомендацию и сохраняет карточку; сервер повторно проверяет пригодность в очереди TaskService, чтобы параллельные назначения не расходовали одни часы.
- Ручное назначение остаётся доступным: предупреждения не блокируют сознательное решение человека.
- Существующие задачи не мигрируют автоматически и не меняют ветки. Поля хранятся в JSON v2, серверная SQLite схема в этой задаче не меняется.

## Проверки

Нужны тесты расчёта, разных проектов/статусов, неизвестных оценок, совпадений групп и технологий,
перегрузки, повторного назначения, конкурирующих запросов, ревизий, безопасного UI и сохранности старых карточек.
Без реальных вызовов GitHub/LLM и без публикации на VPS.
